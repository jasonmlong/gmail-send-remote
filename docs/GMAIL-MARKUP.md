# Gmail markup reference

What Gmail's web compose actually emits, captured from three messages Sam sent in September 2026 (a new message to a contractor, a reply to a vendor, a forward of a scheduling thread) plus one message sent from the Gmail mobile app. Content below is replaced with placeholders; structure, attributes, whitespace and ordering are verbatim. Every rule here is implemented in `src/core` and pinned by `tests/compose.test.ts`.

## Common facts

- Text nodes are escaped as `&amp;`, `&lt;`, `&gt;` and `&#39;` for apostrophes. Double quotes are not escaped.
- URLs and email addresses typed into the body are auto-linked on send: `<a href="URL" target="_blank">URL</a>`, `<a href="mailto:x" target="_blank">x</a>`. Ampersands inside hrefs stay `&amp;`.
- Every message HTML ends with `\r\n` after the outer closing `</div>`. When a message is quoted later, that `\r\n` travels with it (`...</div>\r\n</blockquote>`).
- Dates: `On Fri, Sep 18, 2026 at 7:00 AM` where the character between `7:00` and `AM` is U+202F (narrow no-break space). Weekday and month are 3-letter, no leading zeros, 12-hour clock. The clock is the sending client's timezone: the reply sample resolved to Central, the forward sample to Eastern.
- The text/plain part is generated by Gmail from the HTML: greedy word wrap at 72 columns, `> ` quote prefix, blank quoted lines become a lone `>`, already-quoted lines get another `>` (so `>>`), signature preceded by a line containing `--`.

## New message (desktop web)

```
<div dir="ltr"><div>Hey Marco,</div><div><br></div><div>Body sentence one. Body sentence two.</div><div><br></div><span class="gmail_signature_prefix">-- </span><br><div dir="ltr" class="gmail_signature" data-smartmail="gmail_signature">SIGNATURE_INNER_HTML</div></div>\r\n
```

- Every typed line is its own `<div>`; blank lines are `<div><br></div>`.
- One `<div><br></div>` separates the body from the signature prefix.
- Signature inner HTML is exactly what Gmail stores in Settings (the sendAs `signature` field), unchanged.

Plain text:

```
Hey Marco,

Body sentence one. Body sentence two, wrapped at seventy two columns when it
runs long.

--
SIGNATURE_TEXT
```

Gmail mobile app variant (for recognition only, not generated): `<div dir="auto"><div>Hey Paul,</div><div dir="auto"><br></div>...<div data-smartmail="gmail_signature">--<br>Name<br>Title<br>Company<br>Phone<br>    </div></div>`.

## Reply (desktop web, signature after quoted text, Gmail default)

```
<div dir="ltr">Hey Priya,<div><br></div><div>Thank you for the update.</div><div><br></div><div>Point one.</div><div>Point two.</div><div><br></div><div>Thank you!</div></div><br><div class="gmail_quote gmail_quote_container"><div dir="ltr" class="gmail_attr">On Fri, Sep 18, 2026 at 7:00 AM Priya Nair &lt;priya@example.com&gt; wrote:<br></div><blockquote class="gmail_quote" style="margin:0px 0px 0px 0.8ex;border-left:1px solid rgb(204,204,204);padding-left:1ex">ORIGINAL_MESSAGE_HTML_VERBATIM\r\n</blockquote></div><div><br clear="all"></div><div><br></div><span class="gmail_signature_prefix">-- </span><br><div dir="ltr" class="gmail_signature">SIGNATURE_INNER_HTML</div>\r\n
```

- The first typed line is a bare text node inside `<div dir="ltr">`; only the following lines get `<div>` wrappers (the reply box starts as a text node).
- `<br>` between the body div and the quote container.
- The attribution address is not linked in the owner's sends (`&lt;email&gt;`). Some clients emit `&lt;<a href="mailto:..." target="_blank">email</a>&gt;`; that is available as an option.
- The original message HTML is embedded verbatim inside the blockquote, including its own nested quotes and trailing `\r\n`.
- The after-quote signature block is `<div><br clear="all"></div><div><br></div>` then the prefix then `<div dir="ltr" class="gmail_signature">` (no `data-smartmail` attribute on replies; forwards do carry it).

Plain text:

```
Hey Priya,

Thank you for the update.

Point one wrapped at seventy two columns when it runs long, exactly like
Gmail does it.

Thank you!

On Fri, Sep 18, 2026 at 7:00 AM Priya Nair <priya@example.com>
wrote:

> Hi Sam,
>
> Original text quoted line by line.
>
>> Earlier quoted text gets a second marker.
>

--
SIGNATURE_TEXT
```

- The attribution keeps `Name <email>` intact and only pushes `wrote:` to the next line when the line exceeds 72 columns.

## Reply with "insert signature before quoted text" (Gmail setting)

```
<div dir="ltr">Hey Priya,<div><br></div><div>Body.</div><div><br></div><div><div dir="ltr" class="gmail_signature" data-smartmail="gmail_signature">SIGNATURE_INNER_HTML</div></div></div><br><div class="gmail_quote gmail_quote_container">...</div>\r\n
```

No `-- ` prefix; the signature lives inside the body div; the text part has no `--` line either.

## Forward (desktop web, signature after quoted text)

```
<div dir="ltr">OPTIONAL_NOTE<br><br><div class="gmail_quote gmail_quote_container"><div dir="ltr" class="gmail_attr">---------- Forwarded message ---------<br>From: <strong class="gmail_sendername" dir="auto">Ravi Shah</strong> <span dir="auto">&lt;<a href="mailto:ravi@example.com">ravi@example.com</a>&gt;</span><br>Date: Thu, Sep 10, 2026 at 9:28 AM<br>Subject: Re: Website: 2nd Call<br>To: Lena Ortiz &lt;<a href="mailto:lena@example.com">lena@example.com</a>&gt;, Sam Rivera &lt;<a href="mailto:sam@example.com">sam@example.com</a>&gt;<br>Cc: Owen Clarke &lt;<a href="mailto:owen@example.com">owen@example.com</a>&gt;<br></div><br><br><div class="msg-488889583641520949">ORIGINAL_MESSAGE_HTML_WITH_IDS_PREFIXED</div></div><div><br clear="all"></div><div><br></div><span class="gmail_signature_prefix">-- </span><br><div dir="ltr" class="gmail_signature" data-smartmail="gmail_signature">SIGNATURE_INNER_HTML</div></div>\r\n
```

- Addresses in the header are mailto-linked without `target`.
- The original is wrapped in `<div class="msg-N">` and every `id="X"` inside becomes `id="m_-NX"` (N is an 18 digit number).
- With no note the message starts `<div dir="ltr"><br><br><div class="gmail_quote...`.
- Subject becomes `Fwd: ` + original subject (existing `Fwd:`/`FW:` kept). Attachments are carried over.

Plain text:

```
---------- Forwarded message ---------
From: Ravi Shah <ravi@example.com>
Date: Thu, Sep 10, 2026 at 9:28 AM
Subject: Re: Website: 2nd Call
To: Lena Ortiz <lena@example.com>, Tomas Brandt Whitfield <
Whitfield@example.com>, Sam Rivera <sam@example.com>
Cc: Owen Clarke <owen@example.com>

ORIGINAL_TEXT

--
SIGNATURE_TEXT
```

- Because the header addresses are links, Gmail's wrapper may break a long line right after `<`.

## Signature text conversion rules (observed)

| HTML | Text |
|---|---|
| `<a href="L"><img alt="Northwind Labs"></a>` | `[image: Northwind Labs] <L>` |
| `<a href="L"><img alt=""></a>` | `<L>` |
| `<a href="tel:+1+(555)+010-4477">+1 (555) 010-4477</a>` | `+1 (555) 010-4477 <+1+(555)+010-4477>` |
| `<a href="mailto:x@y">x@y</a>` | `x@y` |
| `<a href="https://sigcdn.example/x">northwind.example</a>` | `northwind.example <https://sigcdn.example/x>` |
| table cells in one row | joined with a single space |
| table rows / `<div>` / `<br>` | one line break |
| `<p>` | blank line |

## Headers (from the MIME Gmail sends)

- `In-Reply-To: <original Message-ID>` and `References: <all earlier ids> <original Message-ID>` on replies.
- `Content-Type: multipart/alternative; boundary="000000000000xxxxxxxxxxxx"` with `text/plain` then `text/html`, both `quoted-printable`, `charset="UTF-8"`.
- Gmail Message-IDs look like `<CA+...=...@mail.gmail.com>`; the simulator mints ids in that shape.

## Known small deviations

- Gmail's wrapper occasionally lets a signature line run to 78 columns when the HTML has span boundaries inside a sentence; this renderer wraps at 72 consistently. Invisible to recipients (they render the HTML part).
- Gmail linkifies phone numbers inside quoted content when displaying, not when sending; not reproduced.
